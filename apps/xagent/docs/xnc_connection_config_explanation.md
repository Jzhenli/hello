# XNC通道连接配置说明

## UI上的"连接配置"部分

### 字段列表
UI上的"连接配置"部分包含以下字段：
1. **主机地址** (`host`)
2. **端口** (`port`)
3. **用户名** (`username`) - 可选
4. **密码** (`password`) - 可选

## XNC协议的特殊性

### ⚠️ 重要说明
对于XNC协议，"连接配置"部分的字段含义与MQTT/HTTP不同：

#### 1. 主机地址和端口
- **实际用途**：表示XNC服务器的地址和端口
- **后端映射**：
  - `host` → `connection.xnc.remote_host`
  - `port` → `connection.xnc.remote_port`
- **作用**：XNC插件使用这两个字段创建UDP发送端点，向XNC服务器发送数据

#### 2. 用户名和密码
- **实际用途**：对于XNC协议，这两个字段**通常不使用**
- **原因**：XNC基于UDP协议，是无连接的，不像MQTT需要认证
- **建议**：配置XNC通道时，可以留空这两个字段

## XNC协议的实际连接流程

### 双向UDP通信
XNC协议使用UDP进行双向通信：

```
┌─────────────┐                    ┌─────────────┐
│  XAgent     │                    │  XNC服务器   │
│             │                    │             │
│  本地端口    │◄────UDP命令────────│  远程端口    │
│  8888       │                    │  9000       │
│             │                    │             │
│             │────UDP数据─────────►│             │
└─────────────┘                    └─────────────┘
```

### 1. 数据上传（发送）
```python
# 使用主机地址和端口创建UDP发送端点
remote_addr = (remote_host, remote_port)  # 例如: ("127.0.0.1", 9000)
send_transport.sendto(data, remote_addr)
```

**配置对应**：
- UI上的"主机地址" → `remote_host`
- UI上的"端口" → `remote_port`

### 2. 命令接收（监听）
```python
# 使用本地端口创建UDP监听端点
local_addr = ("0.0.0.0", local_port)  # 例如: ("0.0.0.0", 8888)
command_transport, _ = await loop.create_datagram_endpoint(
    lambda: UDPCommandProtocol(self),
    local_addr=local_addr
)
```

**配置对应**：
- XNC配置中的"本地端口" → `local_port`

## 配置字段对照表

### UI显示 vs 后端使用

| UI字段 | 后端字段 | XNC用途 | 是否必需 |
|--------|---------|---------|---------|
| 主机地址 | `connection.xnc.remote_host` | XNC服务器地址 | ✅ 必需 |
| 端口 | `connection.xnc.remote_port` | XNC服务器端口 | ✅ 必需 |
| 用户名 | `connection.username` | 不使用 | ❌ 可留空 |
| 密码 | `connection.password` | 不使用 | ❌ 可留空 |
| 本地端口 | `connection.xnc.local_port` | UDP监听端口 | ✅ 必需 |

### 完整配置示例

#### UI填写
```
连接配置：
  主机地址：127.0.0.1
  端口：9000
  用户名：(留空)
  密码：(留空)

XNC配置：
  本地端口：8888
  协议模式：Protobuf
  远程主机：127.0.0.1
  远程端口：9000
```

#### 后端配置结构
```json
{
  "connection": {
    "host": "127.0.0.1",
    "port": 9000,
    "xnc": {
      "local_port": 8888,
      "remote_host": "127.0.0.1",
      "remote_port": 9000
    }
  }
}
```

## 为什么会有重复字段？

### 字段重复的原因
UI上"连接配置"的"主机地址"和"端口"与"XNC配置"的"远程主机"和"远程端口"实际上是**同一个配置**，只是：

1. **UI设计**：为了统一不同协议的配置界面，使用了通用的"连接配置"部分
2. **后端映射**：前端会将这些字段映射到正确的位置
3. **历史原因**：最初设计时考虑了多协议的统一性

### 数据转换逻辑
```typescript
// 前端构建配置时
connection: {
  host: channelForm.value.host,        // 通用字段
  port: channelForm.value.port,        // 通用字段
  xnc: {
    remote_host: channelForm.value.remote_host,  // XNC特定字段
    remote_port: channelForm.value.remote_port   // XNC特定字段
  }
}
```

## 实际使用场景

### 场景1：本地XNC服务器
```
主机地址：127.0.0.1
端口：9000
本地端口：8888
```
- XAgent和XNC服务器在同一台机器上
- XAgent监听8888端口接收命令
- XAgent向9000端口发送数据

### 场景2：远程XNC服务器
```
主机地址：192.168.1.100
端口：9000
本地端口：8888
```
- XNC服务器在远程机器192.168.1.100上
- XAgent监听本地8888端口接收命令
- XAgent向远程9000端口发送数据

### 场景3：NAT环境
```
主机地址：public.example.com
端口：9000
本地端口：8888
```
- XNC服务器在公网
- XAgent在NAT后面
- 需要配置端口转发将外部8888端口映射到内部

## 常见问题

### Q1: 为什么用户名和密码留空？
**A**: XNC基于UDP协议，是无连接的，不像MQTT需要用户名密码认证。如果未来需要认证，会在XNC协议层面实现。

### Q2: 本地端口和远程端口可以相同吗？
**A**: 可以，但不建议。如果相同，可能会造成端口冲突。建议使用不同的端口。

### Q3: 主机地址可以填域名吗？
**A**: 可以，XNC插件会自动解析域名。但建议使用IP地址以减少DNS解析延迟。

### Q4: 需要开放防火墙端口吗？
**A**: 是的，需要开放：
- **本地端口**：用于接收XNC服务器的命令
- **远程端口**：用于向XNC服务器发送数据

### Q5: 如何测试连接？
**A**: 使用UI上的"测试连接"功能，系统会尝试向XNC服务器发送测试UDP包。

## 总结

### 关键点
1. **主机地址和端口**：表示XNC服务器的地址和端口
2. **用户名和密码**：对于XNC协议，可以留空
3. **本地端口**：XAgent监听的UDP端口，用于接收命令
4. **远程主机和端口**：与"连接配置"中的主机地址和端口相同

### 最佳实践
1. 配置XNC通道时，重点填写"XNC配置"部分
2. "连接配置"部分填写XNC服务器地址和端口即可
3. 用户名和密码留空
4. 使用"测试连接"功能验证配置
